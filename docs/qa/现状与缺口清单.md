# Falcon 性能板块 · 现状与缺口清单

> 盘点日期 2026-09-04 · 基于 commit `03d4d23` 全量代码审计 + 生产环境实测
> 配套文档：[功能测试报告](./功能测试报告.md)

## 总体判断

**主干是好的。** JMX 解析 → Step2 真 JMeter 校验 → 三条执行链路 → 终态入库 → 展示端点 → AI 分析，完整闭环，
生产实测数据一致性 7 项校验全过。后端 12,281 行业务代码，架构清晰，`services/` 分层合理。

真正的问题不在"功能没做完"，而在四个方向：

1. **配置没跟上代码** —— 诊断/监控/AI 三大模块在生产全是空配置，等于没上线
2. **做了没入口** —— 15 个后端端点前端零调用，8 个孤儿组件（~1500 行）写完没挂
3. **故障不可见** —— 后端 13 处 + 前端 40+ 处静默 catch，外部依赖挂掉一律伪装成"暂无数据"
4. **零测试零 CI** —— 12,281 行代码 0% 覆盖，每次改动只能靠人工点

## 一、生产配置缺口（最高优先级，改配置即可）

功能都开发完了，但生产没配，用户看不到。**这是投入产出比最高的一块**。

| 配置项 | 生产实测 | 影响的功能 | 怎么补 |
|---|---|---|---|
| `PrometheusDataSource` | **0 条** | 服务诊断的 CPU/内存面板；Step 2「被压测服务」下拉为空 | Admin 里加数据源 |
| `Service` 表 | **0 条** | Pinpoint 拓扑 / JVM / 慢链路无法关联应用 | Admin 里加服务 + `pinpoint_app` |
| `Environment` 表 | **0 条** | hosts 映射，预检永远「未配置，跳过」 | Admin 里加环境 |
| `AI_BASE_URL` / `AI_API_KEY` / `AI_MODEL` | **未配置** | Step 4 AI 分析点了返 503 | K8s ConfigMap + Secret |
| `ORCHESTRATOR_TYPE` | 配的是 `k8s` | 但 `K8sAdapter` 是 stub → 前端「+扩容」必崩 | 改回 `docker` 或实现 adapter |
| `LOCAL_FALLBACK` | 配的是 `1` | 没选 agent 时会在 backend pod 里跑 JMeter，与 4Gi 内存限制撞车 | 生产应设 `0` |

## 二、缺陷（生产实测确认）

详细复现步骤见[功能测试报告](./功能测试报告.md)。

| 编号 | 级别 | 缺陷 | 位置 |
|---|---|---|---|
| BUG-01 | 🔴 严重 | **平均 RPS 虚高 5 倍**（5 秒聚合值被当每秒速率平均），所有历史 run 都受影响 | `influxdb.py:1019-1031` |
| BUG-02 | 🔴 严重 | 生产三大配置全空 → 诊断/监控/AI 模块对用户不存在 | 部署配置 |
| BUG-03 | 🔴 严重 | `scale-up`/`scale-down`/`ssh-refresh` 无鉴权，任何人可销毁压力机、`pkill` 正在跑的压测 | `views.py:1821,1845,1874` |
| BUG-04 | 🟠 一般 | 重复起 run 报「压力源非 idle 请刷新」而非「任务已在运行」，把用户引向错误方向 | `views.py:894` 校验顺序 |
| BUG-05 | 🟠 一般 | `register` 遇畸形 port 直接 500（应 400） | `views.py:1802-1806` |
| BUG-06 | 🟠 一般 | `set-keep`/`set-baseline` 用 `bool()`，字符串 `"false"` 判成 True | `views.py:1088,1096` |
| BUG-07 | 🟠 一般 | p99 两个口径（InfluxDB 区间均值 vs JTL 精确），界面显示不同数字无说明 | `influxdb.py:992` |
| BUG-08 | 🟠 一般 | 预检磁盘显示 10 PB，`<100MB 拒绝` 保护永不触发 | `executor.py` 预检第 3 项 |
| BUG-09 | 🟠 一般 | 预览 XML 与实际执行版不一致（缺 BackendListener/DNS/错误监听器） | `views.py:492` |
| BUG-10 | 🔵 优化 | `PUT /tasks/:id/` 绕过 PATCH 的 rename + JMX 同步逻辑 | ModelViewSet 默认 |
| BUG-11 | 🔵 优化 | `TaskRun.load_generators` 未序列化，前端看不到用了哪几台机器 | `serializers.py` |

## 五、可观测性缺口（系统性问题）

**后端**：`influxdb.py` 有 **13 处** `except Exception: pass`，任何 InfluxQL 语法错误、schema 变更、权限问题都表现为"图表空白"，日志一个字没有。`ensure_retention_policy` 失败静默 → 保留策略没建成也没人知道，直到爆盘。

**前端**：**40+ 处静默 catch**。Pinpoint / Prometheus / InfluxDB / Arthas 任一挂掉，UI 都是"暂无数据"，运维无法自诊断。典型：`SamplersTab.vue:37` 错误聚合失败 → 显示"无错误"；`ReportTab.vue:43` 状态拉不到 → 永久停在"加载中"且无重试。

**日志**：executor 多处用 `print(stderr)` 而非 logging，K8s 里大概率丢失。`_extract_and_persist_analysis` 失败 = 该 run 永远没有 DB 分析行，只能靠文件兜底，而文件 30 天后被清 → **数据永久丢失且无告警**。
